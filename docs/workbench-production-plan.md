# 工作台正式组件与接入方案

状态：阶段 1 已获用户验收；阶段 2 已实施并接入正式 App，阶段 3–5 待顺序实施。以用户确认的交互为准；当前 mock 页复用生产 App，视觉基本认可不代表所有布局行为已实现。保留工作区已有未提交改动，按职责逐阶段接入。

## 分层与接口

通过现有 `renderer/app` 组合入口连接各 Feature；`ui` 负责无业务语义的交互与布局，Feature 负责展示投影和领域交互。继续使用 Desktop Client 和现有 IPC，不新增后端架构层、全局状态库或可任意执行的宿主接口。

| Module / 所在层 | Interface 承担的职责 | 保留的状态所有者 |
| --- | --- | --- |
| 应用页面导航 / app | 工作台与设置页之间导航，记录返回位置，通知视图是否可见 | 应用页面状态；会话选择仍属于 Workspace |
| 工作台组合 / workspace | 连接项目导航、会话内容、环境卡片和工具抽屉，组织用户操作 | 工作台展示控制器 |
| 布局 / ui + workspace | 扩展现有 ResizableWorkspace 的辅助列；统一尺寸、收缩、拖动、焦点与动效 | ui 持测量与拖动；workspace 持用户展开意图 |
| 项目导航 / workspace | 项目分组、整行折叠、会话选中、状态图标、最近项与操作菜单 | useWorkspace 持会话投影；导航控制器持折叠与最近区状态 |
| 环境卡片 / workspace | 接收仓库、后台终端、来源的展示投影，报告明确的操作意图 | 环境控制器持读取和 Git 操作状态 |
| 工具抽屉 / workspace | 基于同一类型化工具清单展示入口、标签页和对应内容 | useSidePanelTabs 持按 session/draft 隔离的标签状态 |
| 对话 / conversation | 分开内容展示、过程分组、编辑器和运行时控制 | 保留 ChatPane 的流式投影、草稿 revision、附件和提交生命周期 |
| 设置页 / preferences | 外观、运行时配置、归档列表各自展示并调用所属控制器 | useSettingsDraft、归档操作控制器 |

只拆能隐藏完整职责的 Module：环境读取与操作、过程分组、布局适配、归档管理。简单 JSX 留在所属模块；不按每一行、每一个按钮建立文件，不创建只透传整包 props 的 wrapper。

## 页面与导航关系

通过应用内存中的类型化页面状态表达 `workbench` 和 `settings`；当前没有外部深链接需求，不引入 URL 路由库。后续需要深链接时再通过经过校验的入口映射到同一导航接口。

- 打开设置页时保存工作台返回位置；返回时恢复原项目、会话、草稿和面板选择。设置页具备正常的页面内容与导航语义，重命名现有 SettingsDialog 为 SettingsPage 并迁移导出与调用方。
- 项目展开/折叠只改变导航展示；点击会话通过现有 Workspace 选择接口导航。新对话仍是本地草稿，发送首条消息后才创建 Pi 会话。
- 项目/会话前进后退沿用 Workspace 历史；页面返回与会话历史分开记录，避免“打开设置”制造虚假的会话历史。
- 工具标签、搜索、命令面板、确认 Dialog 是工作台的局部状态，不成为独立页面路由。跨会话的抽屉状态继续使用 session ID 或 draft cwd 隔离。
- 导航隐藏工作台时保留会话 owner 与草稿，不重启 Pi、重复订阅或重建 PTY。通过明确的页面可见性通知暂停不可见视图，并将原生 BrowserView bounds 清空；不能靠一个 CSS 遮罩盖住原生网页。返回后恢复合法的 bounds 与终端几何。

## 布局契约

通过正常的网格列建立“项目导航 → 对话 → 环境卡片所在辅助列 → 工具抽屉”的关系。环境列位于对话和抽屉之间；卡片靠顶部，保持约 300px 的内容宽度、圆角和有限阴影，按内容决定高度。列本身不画整高边框或独立背景，不使用 absolute、fixed 或 Portal 覆盖对话，也不把整个对话内容向下推。

- 在现有 ResizableWorkspace 内扩展一个受限的辅助列 slot，统一计算可用宽度与可见列；workspace 只提供列内容、尺寸约束和展开意图，不复制第二套宽度检测。
- 保留当前对话最小宽度 360px、项目最小宽度 180px、抽屉最小宽度 280px；列间距计入总宽度。优先使用用户保存的宽度，辅助列没有独立拖动手柄。
- 宽度不足以维持当前主要列和环境列时先隐藏环境列，然后按现有规则压缩主要列；仍不足时收起抽屉，最后收起项目导航。拖动抽屉时同样先让环境列退出，保证对话可读。
- 区分“用户希望显示”和“当前宽度允许显示”：自动收起只改变实际可见性，空间恢复后自动恢复；手动关闭后不自动重开。顶部图标反映实际显示状态，并说明空间不足时的恢复行为。
- 环境内容过长时只在卡片内滚动；列保持在自己的布局位置，Composer 继续停靠对话区底部。点击对话或抽屉不关闭卡片，顶部图标控制显示与隐藏。
- 自动收起前将列内焦点转移到永久存在的顶部开关；隐藏列设为 inert，保留已有菜单与 Dialog 的 Escape、IME 和焦点规则。沿用现有 GSAP seam 与 reduced-motion 约定。

## Feature 拆分与行为契约

### 环境卡片

将现有 EnvironmentPopover 拆成 EnvironmentCard、环境读取/操作控制器和 Git 确认流程；组件名称与实际形态一致。卡片不调用真实 Pi/Git，只消费投影和类型化操作。控制器复用 Desktop Client，保留主进程的会话、路径、空闲和 dirty worktree 校验。

仅在卡片实际可见且有有效 session 时读取仓库信息。读取和每次操作都捕获目标 session ID；会话变化或关闭后，旧结果不写进新卡片。后台完成的操作仍作用于原目标，不通过“当前会话”重新定向；错误、确认目标与 busy 状态按操作归属管理。

移除 Collaboration；Background processes 仅存在存活终端时显示；Sources 仅存在真实来源时显示，当前可核实的来源是会话 cwd。不伪造浏览器历史、附件索引或尚未接入的添加来源能力。

### 项目导航与会话状态

通过导航控制器生成稳定的项目与会话展示投影，ProjectSidebar 只组合项目行、会话行与菜单。项目以完整 cwd 为身份，会话以 host ID 为身份；显示名称不承担身份职责。

项目整行仅展开/折叠；更多操作和新建按钮作为独立兄弟控件。只给会话行选中状态。状态图标及说明来自同一个状态映射，避免并列显示多个矛盾标记；最近列表只显示会话名称。

钉选、归档、改名继续调用原来的真实操作；失败保留条目，关闭执行中的会话沿用既有确认。没有宿主能力的菜单项不展示。整理未提交界面中的硬编码 Codex、Full access 等文案，仅展示 PUA 的真实产品语义。

### 工具抽屉

通过同一类型化清单定义终端、浏览器、Git Diff 的入口、标签和内容映射；首页与添加菜单消费同一清单，避免 string 强转和多重三元分支漂移。

工具能否打开由真实上下文决定：Git Diff 需要合法会话；终端复用现有 Terminal Session 的唯一 PTY，不把占位页当可用终端；浏览器保持独立 WebContentsView 的隔离和销毁协议。不展示 Suggested 或虚构快捷键。

任务详情等已有专用调用暂时保留其明确入口，不加入公共工具清单；移除旧入口前逐一核对调用者，避免借“仅三个工具”删除仍被真实流程使用的能力。

### 对话与设置

继续复用 Composer，不复制 pending/IME/草稿清理实现。将附件与扩展命令统一为类型化动作清单，插入命令与执行命令分开；plan/goal 根据 Pi 提供的命令显示，compact/stats 沿用现有本地协议。

通过只读的过程分组投影把思考与工具执行组合到 Worked for 摘要，正文展示和运行中状态分开。提取呈现职责时保留工具失败、流式末段、历史与输出复制，不重写 Conversation reducer 或业务协议。

设置页将归档管理从表单展示中拆出，使恢复/删除状态与配置保存状态独立；失败保留草稿，保存后经原 bootstrap 发布结果，凭据与 Pi 的模型/工具配置继续由 Pi 管理。

## mock 与正式接入

在隔离预览入口注入内存 Adapter，使同一批正式展示组件同时接受 mock 投影和桌面控制器结果。生产入口不导入 fixture，不通过 location/query 参数选择假数据；保持目前 Fake Desktop 的宿主隔离，逐步补充明确的场景入口。

预览覆盖宽窗、环境优先收起、抽屉拖动、窄窗恢复、长卡片、无来源/无后台进程、有后台进程、长会话名、运行/等待/错误、富文本和局部失败。记录场景与同视口截图，不把单次截图或类型检查当功能验收。

## 阶段 1 实施记录（2026-10-14）

提交只包含本阶段新增接口、组合、样式 hunk、隔离预览压力场景、浏览器/桌面验收脚本及文档；既有导航、主题、Composer、图标和预览数据未夹带。为确认不依赖未提交内容，另从 index 构造独立候选树验证。
