# Codex Desktop 交互对齐清单

状态：目标契约（2026-09-14）。本清单描述 PUA 要复刻的 Codex Desktop 工作台交互；Pi 不提供的模型、凭据、工具和扩展能力不在范围内。

## 目标

PUA 的一级对象是任务（Task），项目（Project）用于分组，Pi 会话（Session）是任务开始工作后的运行资源。点击项目只进入该项目的本地未提交对话草稿，不创建 Pi 会话或历史记录；用户首次发送消息/开始工作时才创建真实会话并写入历史。这样重复点击项目不会产生空白历史，同时会话切换仍不丢失草稿、附件、滚动位置、运行状态或检查器状态。

## 能力矩阵

| 区域 | 目标行为 | 当前缺口 |
|---|---|---|
| 全局导航 | 新任务、搜索、最近、归档、项目分组、折叠与恢复 | 仅 ProjectNav |
| 项目树 | 项目展开后显示全部任务，当前项目与当前任务独立高亮 | 已使用项目下二级会话列表；分支树仍按 Pi entry 投影 |
| 任务生命周期 | 创建、恢复、关闭、归档、取消归档、置顶、重命名 | 仅内存创建/关闭/重命名 |
| 任务栏 | 标题、项目、分支、运行状态、分享、更多操作 | 无任务级操作栏 |
| 对话 | 消息操作、工具过程、重试/继续/停止/排队、附件与命令 | Pi 能力分散在 ChatPane；压缩上下文与当前会话统计已通过 Pi 原生 RPC 接入 |
| 检查器 | 变更、文件、分支、终端与任务上下文联动 | GitPanel 独立 |
| 搜索 | 全局任务、项目内任务、当前对话/终端 | 仅命令菜单与终端搜索 |
| 后台状态 | 离开任务后保留运行、完成、失败、通知 | 仅当前 Session activity |
| 恢复 | 重启后恢复最近任务、布局、草稿与面板状态 | 当前已持久化最近项目和项目折叠 UI 投影；Pi 历史仍由 Pi 管理，原生 session identity 恢复待接入 |
| 键盘 | 新任务、切换任务、搜索、聚焦输入、归档、关闭、面板切换 | 已补齐原生 Cmd/Ctrl+N 项目草稿入口；任务归档/关闭等仍受产品语义决策约束 |
| 窄窗 | 面板可发现、渐进收缩、状态不丢失 | 入口曾被隐藏 |

## 不可复刻边界

Pi 不支持的云端分享链接、远程任务同步、模型账户与 Codex 服务能力不伪造入口。PUA 只实现本地任务管理、Electron 窗口交互、Pi RPC/PTY、Git 与文件系统可支持的体验。

## Pi 能力盘点与差异决策记录

这张表是实施前置条件。新增 Codex 交互时必须先更新“决策”列，不能默认 Pi 已支持。当前已核对仓库中的 Pi 0.85.1 RPC 接入记录与 `docs/native-chat-design.md`；版本升级后必须重新核对。

| Pi 当前可确认能力 | PUA 可直接编排的交互 | Codex 可能有但 Pi 未确认的能力 | 决策 |
|---|---|---|---|
| 新建/继续/恢复会话 | 新任务、最近任务、恢复任务 | 云端任务同步 | 仅做本地；云端另行讨论 |
| 会话重命名 | 任务标题编辑与列表展示 | 自动标题生成服务 | 本地标题先支持；自动生成待讨论 |
| prompt / steer / followUp / stop | 发送、排队、继续、停止 | 远程后台执行 | 本地运行态支持；远程能力待讨论 |
| streaming 消息、thinking、tool、extension UI | 消息流、工具过程、等待输入 | Codex 专属工具卡片 | 复用 Pi 事件；不伪造 Pi 不提供的字段 |
| 附件登记、发送、移除 | Composer 附件和引用 | 云端文件索引 | 本地文件支持；索引待讨论 |
| session history / terminal PTY | 历史恢复、兼容终端 | 跨设备历史 | 仅本机 |
| Pi trust、model、skills、extensions | 在会话中展示/响应 | Codex 账户权限与用量 | 交由 Pi；账户能力不实现 |
| Git status / diff（PUA Adapter） | 检查器、文件 diff、引用反馈 | Codex 自动 patch review | 只做可验证的本地 Git 闭环 |

已确认的 Pi RPC 事件/语义还包括：delta streaming、thinking、tool 生命周期、agent settled、compacting/retry、steer/followUp 队列、clear queue、history snapshot、session name、extension UI（select/confirm/input/editor/notify/status/widget/title/editor text）。这些能力应优先做 PUA 的完整可发现交互，而不是等待 Codex 对照；TUI custom renderer/header/footer/theme 与 custom editor 没有原生 RPC 等价，继续保留兼容终端入口。

### 必须另行讨论的产品差异

以下项目不能在后续实现中自行假设，需单独做产品决策并记录结果：任务是否跨重启持久化 Pi 历史、是否提供本地分享/导出、自动标题生成规则、任务删除与归档语义、后台任务是否允许应用退出、多个窗口是否共享任务列表、以及 Codex 没有但 PUA 因本地 Pi 而新增的终端/信任/诊断入口。

### 证据来源

当前表格只是仓库接入能力的初步盘点，**不是 Pi 完整能力审计**；当前 PUA 没有接入某功能，不等于 Pi 不支持。尚未核对安装版本的 Pi 官方协议、CLI、SDK 与扩展文档，也未完成专项运行验证。Codex 桌面应用的 Computer Use 检查被工具拒绝，不能把截图以外的交互当作已实测。

### Pi 特有能力：下一实施阶段前完成

1. 确定用户实际安装的 Pi 版本和官方文档来源，分别调查 RPC、CLI/TUI、SDK、扩展接口；记录版本、命令/事件、来源和限制。
2. 重点核验会话树/分支与 fork、上下文压缩、模型与思考级别切换、技能/提示模板、扩展命令和自定义 UI、队列策略、会话导出及用量统计。以上是调查候选项，并非已经确认全部支持。
3. 对每项分别记录 Pi 是否支持、PUA 是否接入、Codex 是否观察到等价交互。Codex 未观察到不等于不存在；Pi 特有能力也不因缺少 Codex 对照而被删去。
4. 对“Pi 有能力、Codex 无等价入口或交互不同”的项目，提出 PUA 入口、工作流与取舍，单独与用户讨论后记录决定；保留现有 Pi 能力。
5. 决策记录至少包含能力 ID、证据与版本、接入方式、拟议入口、状态（待核验/待讨论/已批准/暂缓）、用户决定、关联实施阶段与验收标准。依赖未决能力的实现等待该决定，不影响独立工作。

Pi 能力审计完成前，不将 Task DTO、历史恢复映射或能力排除清单视为最终契约。若审计揭示模型不匹配，应先修订目标架构再实施。新增协议接口只同步其实际涉及的 DTO、schema 和 Adapter，不机械修改所有协议文件。

## 验收原则

每项能力必须有鼠标和键盘路径；异步操作必须显示 pending、成功、失败和恢复；任务切换必须验证身份与草稿 revision；应用重启必须验证持久化恢复；窄窗必须验证功能仍可发现。
